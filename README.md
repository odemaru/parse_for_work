# Мониторинг вакансий продуктового и дата-аналитика

Раз в сутки обходит карьерные сайты компаний, отбирает вакансии продуктового
аналитика и аналитика данных и присылает в Telegram только то, чего не было
в прошлый раз. (не для себя)

## Источники

| Компания | Откуда берутся вакансии |
|---|---|
| Wildberries | `career.rwb.ru/crm-api/api/v1/pub/vacancies` |
| X5 / Пятёрочка | `rabota.x5.ru/api/v2/public/vacancies/` (серверный поиск) |
| МТС | `job.mts.ru/api/v2/catalog/v1/vacancies` |
| Магнит | `rabota.magnit.ru/api/v1/vacancy` |
| Т-Банк | sitemap карьерного раздела |
| Lamoda | `job.lamoda.ru/sitemap.xml` |
| Северсталь | HTML листинга `career.severstal.com/vacancies/` |

Ozon и Альфа-Банк не подключены: `career.ozon.ru` отдаёт заглушку «Скоро
что-то будет» и заворачивает прямые запросы антиботом, а домены `alfabank.ru`
не резолвятся за пределами РФ. Оба описаны в `watcher/config.py` — когда
доступ появится, останется добавить модуль в `watcher/sources/` и вписать
его имя в `ENABLED_SOURCES`.

## Установка

1. Создайте репозиторий и положите туда содержимое этой папки.
2. Заведите бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
3. Напишите боту любое сообщение, затем узнайте свой chat id:

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | grep -o '"chat":{"id":[-0-9]*'
```

4. В репозитории откройте Settings → Secrets and variables → Actions и добавьте
   `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Чтобы уведомления уходили нескольким
   адресатам, перечислите их id в `TELEGRAM_CHAT_ID` через запятую — каждый
   из них должен сам написать боту хотя бы раз, иначе Telegram не примет
   сообщение.
5. Запустите workflow вручную (Actions → Мониторинг вакансий → Run workflow).

Первый запуск ничего не присылает списком: он запоминает всё, что уже висит на
сайтах, и сообщает только сколько вакансий взял на карандаш. Начиная со второго
запуска приходят исключительно новые.

## Как отбираются вакансии

Т-Банк и Lamoda не отдают названия — только транслитерированный slug из URL,
причём по разным схемам (`produktovyj` против `produktoviy`). Поэтому все
названия приводятся к латинице, схемы сводятся к общему виду, и дальше ищутся
корни слов: нужен корень роли (`analitik`, `analyst`) и корень предметной
области (`produkt`, `dann`, `data`).

## Как отбирается опыт

Нужны вакансии, куда берут с опытом до трёх лет включительно. Опыт публикуют
не все: МТС, Wildberries, X5 и Северсталь отдают его полем, а Т-Банк, Lamoda
и Магнит — нет. Поэтому он оценивается с двух сторон:

- **по полю**, когда оно есть. Форматы разные — от «От 1 года до 3 лет»
  у Северстали до прозы вроде «Опыт работы BI-аналитиком от 2 лет» и «от двух
  лет» у X5, — поэтому из строки вытаскивается нижняя граница в годах;
- **по грейду в названии**, который есть всегда. «Стажёр», «Junior» и
  «Intern» проходят независимо от поля, а «Senior», «Lead», «Тимлид»,
  «Руководитель», «Старший», «Ведущий» и «Главный» отсекаются — именно так
  фильтруются Т-Банк с Lamoda, где поля нет.

Граница включающая: `MAX_EXPERIENCE_YEARS = 3` пропускает и «1–3 года»,
и «От 3 лет», потому что с ровно тремя годами на такую вакансию берут. Если
нужны только младшие позиции — поставьте `2`.

Вакансии без указанного опыта показываются: `KEEP_UNKNOWN_EXPERIENCE = True`.
Лучше лишняя строка в дайджесте, чем пропущенная вакансия. Поставьте `False`,
если хотите видеть только те, где опыт указан явно.

## Кнопка «Показать все вакансии»

Под уведомлением висит кнопка, открывающая страницу со всеми актуальными
вакансиями — сгруппированными по компаниям, со ссылками, городом и опытом.
Страница публикуется на Telegraph, сервисе самого Telegram, и разворачивается
прямо в чате.

Живой кнопки, по нажатию которой бот присылает сообщение, здесь быть не может:
для этого нужен процесс, который слушает Telegram в момент нажатия, а Actions
просыпается раз в сутки. Кнопка-ссылка даёт тот же результат мгновенно и без
сервера.

## Сводка по источникам

Чтобы бот прислал, с каких компаний он берёт вакансии и сколько их сейчас
в каждой, запустите workflow вручную с галочкой «Прислать в чат сводку».
Состояние при этом не меняется — дедупликация не собьётся.

Локально то же самое: `python -m watcher --announce`. Если секреты Telegram
не заданы, сводка просто печатается в консоль.

Тот же перечень есть в подвале страницы, которая открывается кнопкой
под уведомлением, — вместе с причинами, по которым Ozon и Альфа-Банк
пока не подключены.

## Настройка фильтров

Настраивается в `watcher/config.py`:

- `DOMAIN_ROOTS` — что считать своей областью. Чтобы ловить ещё и BI, допишите
  сюда `"bi "`.
- `EXCLUDE_ROOTS` — что отсекать. Сейчас отсеиваются системные, бизнес-,
  финансовые и маркетинговые аналитики, а также «продуктовое качество»
  из розницы, где «продуктовый» — про еду.
- `MAX_EXPERIENCE_YEARS` и `KEEP_UNKNOWN_EXPERIENCE` — планка по опыту,
  описана выше.

Проверить, что правки ничего не сломали:

```bash
python -m unittest discover -s tests
```

## Локальный запуск

```bash
pip install -r requirements.txt
python -m watcher --dry-run
```

`--dry-run` печатает найденное и не трогает ни Telegram, ни файл состояния.
Отдельный источник — `python -m watcher --dry-run --source mts`.

## Состояние

`data/seen.json` хранит ключи уже показанных вакансий и дату последней встречи;
workflow коммитит его обратно в репозиторий. Записи, не встречавшиеся дольше
`STATE_TTL_DAYS` (по умолчанию 180 дней), удаляются, чтобы файл не рос.

## Если источники начнут падать

Упавший источник не роняет остальные: ошибка попадает в отчёт workflow и
в конец telegram-сообщения. Раннеры GitHub находятся за пределами РФ, поэтому
часть сайтов со временем может начать отвечать 403 — в этом случае помогает
self-hosted runner на машине с российским IP.
